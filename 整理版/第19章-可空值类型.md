<a id="c19-empty"></a>
## struct 为什么能表示“无值”

用户的观察正确：`Nullable<T>`是值类型。对于非可空值类型T，C#的`T?`写法表示`System.Nullable<T>`；null字面量可隐式转换为这个类型的**空值状态**，并非把它变成一个引用类型。

```csharp
Nullable<Int32> y = null;
```

转换结果满足`HasValue=false`。可把它理解为“现在没有一个T值”，和引用类型变量持有null引用是不同的类型语义。[null字面量转换规范](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/conversions#1027-null-literal-conversions)

<a id="c19-shape"></a>
原问答的简化形状保留为**概念示意**，不是重新实现System.Nullable、固定字段布局或完整API。表达式体是C#6语法，其中throw表达式要C#7；第四版C#5可用普通getter和if/throw表达同样的Value检查。

```text
public struct Nullable<T> where T : struct
{
    private readonly T _value;
    private readonly bool _hasValue;

    public bool HasValue => _hasValue;
    public T Value => _hasValue ? _value : throw new InvalidOperationException();
}
```

它说明存在“有值标记”和“保存T值”的两个角色：空值默认状态的标记为false，存储值为default(T)。**不能在HasValue=false时把Value当合法的T读取**；Value会抛InvalidOperationException，GetValueOrDefault则能取默认值。字段名字、顺序、readonly和完整成员是实现细节；固定[.NET10 Nullable实现](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/System.Private.CoreLib/src/System/Nullable.cs)与这份简化图不必逐字相同。

<a id="c19-default"></a>
## new Nullable<int>() 与 default 是语义等价

原三个写法分别保留，属于独立声明对照；同一作用域不要重复定义y：

```csharp
Nullable<Int32> y = null;
```

```csharp
Nullable<Int32> y = new Nullable<Int32>(); // HasValue = false
```

```csharp
Nullable<Int32> y = default; // 现代C#7.1 default literal，效果相同
```

第四版语境可写`default(Nullable<Int32>)`，也可写`default(Int32?)`。这些写法都能得到空值；这不保证编译器真的调用某个无参构造器，更不表示在托管堆上为每个y分配对象。

作者用两个compiler环境分别编译返回null、new Nullable<int>()、default(Nullable<int>)的三方法，实际IL相同：

```il
ldloca.s 0
initobj System.Nullable`1[System.Int32]
ldloc.0
ret
```

这是本机Framework csc与.NET10 Roslyn的具体产物，说明原“编译器帮你new/走构造函数”的描述只能作为默认值语义类比。它不是所有编译器/JIT必须发出相同指令、所有变量位置或全部分配行为的保证。

<a id="c19-memory"></a>
### 类型规则不是“内存放不了 null”

原答说“栈上/结构体内存里放不了引用类型null语义”，这个原因错误。struct可以含引用字段，该字段可以为null；值类型值也不一定都在栈上，可能在对象字段、数组元素等位置。Nullable的空状态由其类型表示，能否把null字面量赋给某个变量由语言转换规则决定。

**补充反例**保留区别，不替代原S负例：

```csharp
struct ReferenceField { public string Text; }
ReferenceField r = default(ReferenceField);
Console.WriteLine(r.Text == null); // True
```

前面声明与运行语句需分别处于类型/方法上下文。本机两环境均确认引用字段可为null，没有执行危险内存访问或推测物理对象布局。

<a id="c19-ordinary-struct"></a>
## 原普通 S 仍不能直接赋 null

原没有任何用户转换的空struct保留为明确失败片段：

```csharp
struct S { }
// 放在方法内：
S s = null; // 预期编译失败：没有适用的转换
```

本机旧compiler真实CS0037。正确方向是“null字面量没有预定义转换到这个普通非可空S”，不是原句“值类型没有到null的转换”；这里需要的是从null到S。

原“只有Nullable认这个转换/特权”指Nullable专门的预定义空态、装箱及提升运算规则，不能推广给所有struct。用户定义转换是另一条路径，不否定Nullable的这些特殊规则。**补充用户转换例**：

```csharp
struct WithNullConversion {
    public string Text;
    public static implicit operator WithNullConversion(string text) {
        return new WithNullConversion { Text = text };
    }
}
// 方法内：
WithNullConversion s = null;
Console.WriteLine(s.Text == null); // True
```

语言先可将null转换到string，再调用string→WithNullConversion用户定义转换。本机两环境都成立；这个S样式结构体仍不是Nullable，也没有自动取得Nullable的HasValue、装箱或提升运算规则。

<a id="c19-constraint"></a>
Nullable的T受`where T:struct`约束，要求非可空值类型；string不能作为T，Nullable<int>本身也不能再用作Nullable的T。作者两个相应补充负例均为CS0453，不把这些额外类型例伪称原问答已有代码。可空值类型与泛型约束的关联见[第12章](第12章-泛型.md)。

<a id="c19-boxing"></a>
## 空值装箱会产生真正的 null 引用

原例完整保留：

```csharp
Nullable<Int32> y = null;
object o = y; // HasValue=false，装箱转换结果为null引用
Console.WriteLine(o == null); // True
```

这次o是引用类型变量，确实获得null引用；不是创建一个保存“空Nullable<int>”的普通箱子。本机两运行时均输出True。反方向将null对象拆箱到int?，得到HasValue=false的空状态；因此可以在值语义与装箱结果之间往返，不能把“没有箱子”误说成y本身是个null引用。

开场同时提到有值情况：int?含5时，装箱结果是一个盒装Int32，而不是盒装Nullable<Int32>；相容的盒装Int32也可拆箱到int?。GetType在这个有值对象上返回System.Int32，由真实装箱/对象类型语义决定，不是反射随意“撒谎”。空可空值调用GetType会因空装箱接收者产生NullReferenceException。接口导读的关联是可以通过相应盒装T调用T实现的接口，不能据此说Nullable<T>自己声明了T的所有接口。[官方装箱/拆箱说明](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/nullable-value-types)

作者的补充探针确认盒装5/GetType为Int32、拆回值5、IComparable对5比较为0；这只核已有导读涉及的机制，没有把所有接口调用或GC实现扩写成新整节教材。值/引用基础见[第5章](第05章-基元类型、引用类型和值类型.md)。

<a id="c19-add"></a>
## 混合邀请中的原 5/null 加法例

末尾虽然在邀请继续讨论，仍带有独立技术输入，完整保留：

```csharp
int? a = 5;
int? b = null;
int? result = a + b;
Console.WriteLine(result.HasValue); // False，result为空
```

这是提升后的可空整数加法：操作数有空值时结果为空，不因读取空值的Value而抛异常。它不证明所有一元/二元/关系操作符完全同样处理null；开场只提出这些规则作为后续主题，并未逐项展开。`a==null`为false、`b==null`为true也属于可空运算规则，而不是两个struct变量做引用身份比较。

## 未展开主题的有界导读

两轮来源还提出以下关联，这些技术提纲保留，不把开场整轮排成寒暄：

- `T?`、一元/二元/关系运算符及其编译展开：实际已展开的5/null加法见前段，其余须按每个操作符规则理解，未编造原IL或输出。
- `??`为空值选择替代值，和条件运算`?:`可以表达某些相同意图；没有本源基准支持`??`一定更快。补充探针a5??0得到5、bnull??0得到0，不声称测了性能。
- EF/数据库nullable列可对应可空值类型；数据库NULL、DBNull对象与C#不同类型中的null语义要按API处理，本源未给数据库程序，不冒称实跑映射。
- C#8 nullable reference types（如启用可空分析时的string?）主要提供引用类型的静态分析/注解，不是把string变成Nullable<string>；与第四版这里的可空值类型分开。
- 和第12章泛型、第5章值/引用、第21章GC有关：Nullable是值类型，是否装箱及含引用字段会影响对象可达性/分配，但本源没有GC调度或速度测量。第21章阅读入口见[目录](README.md#chapter-21)。
