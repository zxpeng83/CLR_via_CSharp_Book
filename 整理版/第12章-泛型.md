## 泛型支持算法重用，T是类型参数

泛型让算法定义者先描述排序、比较、交换、转换或集合管理的规则，再由使用者提供类型实参。`List<T>`里的T是类型参数；`List<int>`中的int是类型实参。可与`void M(int x)`中的值参数x类比：x接收值，T接收类型，二者不是同一种变量。

原章概览的四个优势是：消费者使用泛型程序集通常无需原.cs源码；类型约束与签名使不兼容值可在编译时被拒绝；减少object转换使代码清楚；采用具体值类型参数的路径可避免非泛型object容器引入的装箱/拆箱。泛型算法内部若显式把T转object，仍可能装箱；“泛型”不是全程序不分配、不装箱或总更快的保证。

<a id="c12-fcl"></a>
### FCL中的泛型

System.Collections.Generic提供List<T>等集合，System.Collections.ObjectModel提供适合对象模型的泛型集合，System.Collections.Concurrent提供各自有并发契约的集合。采用泛型集合并不自动让所有业务复合操作线程安全。System.Array也有静态泛型Sort<T>、BinarySearch<T>，不只有泛型类才能包含泛型算法。

以下完整程序保留Sort/搜索入口的含义：

```csharp
using System;
class Program {
    static void Main() {
        int[] values = { 3, 1, 2 };
        Array.Sort<int>(values);
        Console.WriteLine(string.Join(",", values));
        Console.WriteLine(Array.BinarySearch<int>(values, 2));
    }
}
```

输出`1,2,3`和索引1；二分搜索要求已按相应比较规则排序。ArrayList向List<T>迁移并不等于删除旧接口，后文保留向后兼容的IList场景。

<a id="c12-supported"></a>
### 泛型类型和泛型方法是两个层次

原问要求逐项理解CLR支持哪些构造。以下是**类型片段**，保留Container、Pair、IComparator和自定义三参数委托四个例子。

```csharp
class Container<T> { public T Value; }
struct Pair<T> { public T First; public T Second; }
interface IComparator<T> { int Compare(T x, T y); }
delegate TResult MyFunc<T1, T2, TResult>(T1 a, T2 b);
```

class是引用类型，struct是值类型；List<T>与KeyValuePair<TKey,TValue>分别是实际类库例。接口描述实现者应提供的成员，委托描述回调签名；不能把委托对象说成完全没有目标/调用列表存储的“纯方法表指针”，也不能把现代接口的所有能力概括成无实现的空合同。

原章导读还列出委托特殊类的四个成员形状：构造器、Invoke、BeginInvoke、EndInvoke。Framework历史路径支持这套Begin/End异步调用，现代.NET虽可见方法形状，调用BeginInvoke会抛PlatformNotSupportedException；详见已核验的[第11章对应说明](第11章-事件.md#c11-lowering)。这不是可普通class直接继承MulticastDelegate的替代源码。

泛型方法把类型参数放在方法名后，外围类型可以不是泛型。下面完整程序保留Calculator.Max<int>(3,5)、值类型里的方法和接口里的方法。

```csharp
using System;
class Calculator {
    public T Max<T>(T a, T b) where T : IComparable<T> {
        return a.CompareTo(b) >= 0 ? a : b;
    }
}
struct ValueAlgorithms {
    public T Identity<T>(T item) { return item; }
}
interface IFoo { T Identity<T>(T item); }
class Program {
    static void Main() {
        var c = new Calculator();
        Console.WriteLine(c.Max<int>(3, 5));
        Console.WriteLine(c.Max(3, 5)); // 从参数推断T=int
        Console.WriteLine(new ValueAlgorithms().Identity("hello"));
    }
}
```

输出5、5、hello。方法体须有合法返回路径，原`class Foo { T M<T>() {} }`/struct同式只是位置示意，不能作为完整可编译实现。思考区还提出`Point<T>.Distance<T>(...)`：方法可以另声明类型参数，但同名T会遮蔽外围T，容易混淆；Distance需要自己的数值算法/约束，不能仅凭两个T就假定可以相减。可用不同名的类型片段说明两个参数确实独立：

```csharp
struct Point<TCoordinate> {
    public TCoordinate X;
    public TResult Convert<TResult>(System.Func<TCoordinate, TResult> converter) {
        return converter(X);
    }
}
```

<a id="c12-enum"></a>
### enum不能声明自己的类型参数，嵌套泛型类型要分开看

原`enum E<T> { A,B }`及ErrorCode<T>例都不是合法C#；枚举声明没有独立类型参数列表，其底层是指定的整数类型，成员是相应常量。原声称诊断必为CS1912不准确，这种非法语法可先产生语法诊断。

```text
// 反例：不存在这种C#泛型枚举声明语法
enum ErrorCode<T> { None = 0, Fail = default(T) }
enum E<T> { A, B }
```

但这不等于枚举不能出现在泛型类内，也不等于反射看到的所有枚举都必定IsGenericType为false。下面完整程序在Framework与.NET10均验证了这个边界。

```csharp
using System;
class G<T> { public enum E { A, B } }
class Program {
    static void Main() {
        Console.WriteLine(typeof(G<int>.E).IsGenericType);
        Console.WriteLine(typeof(G<int>.E).ContainsGenericParameters);
        Console.WriteLine(typeof(G<int>.E) != typeof(G<string>.E));
        Console.WriteLine(G<int>.E.B);
    }
}
```

输出True、False、True、B。E未声明自有类型参数，CLR表示仍带外围类型上下文；G<int>.E与G<string>.E是不同类型。对原书“不允许泛型枚举”的概括，应以“不能像class/struct那样为enum自声明T”的教学范围理解，避免跨越此边界。[.NET泛型与嵌套类型](https://learn.microsoft.com/en-us/dotnet/standard/generics/)

<a id="c12-list"></a>
## List<T>中T可用于参数、数组返回值、字段和局部变量

原对话把同一个List骨架分别展示为Add、ToArray、索引器和SwapLastTwo。下面完整教学程序合成同一类型，保留所有不同操作及其条件；没有把未初始化数组或缺失_size的片段当成能运行的BCL实现。

```csharp
using System;
public class SimpleList<T> {
    private T[] _items = new T[4];
    private int _size;
    public void Add(T item) {
        if (_size == _items.Length) Array.Resize(ref _items, _items.Length * 2);
        _items[_size++] = item;
    }
    public T[] ToArray() {
        T[] result = new T[_size];
        Array.Copy(_items, result, _size);
        return result;
    }
    public T this[int index] {
        get { Check(index); return _items[index]; }
        set { Check(index); _items[index] = value; }
    }
    private void Check(int index) {
        if (index < 0 || index >= _size) throw new ArgumentOutOfRangeException("index");
    }
    public void SwapLastTwo() {
        if (_size < 2) throw new InvalidOperationException("Need at least two items");
        T temp = _items[_size - 1];
        _items[_size - 1] = _items[_size - 2];
        _items[_size - 2] = temp;
    }
}
class Program {
    static void Main() {
        var ints = new SimpleList<int>(); ints.Add(1); ints.Add(2);
        ints.SwapLastTwo(); Console.WriteLine(string.Join(",", ints.ToArray()));
        var strings = new SimpleList<string>(); strings.Add("Hello"); strings.Add("World");
        strings[0] = "hello"; Console.WriteLine(strings[0]);
        Console.WriteLine(strings.ToArray().GetType().Name);
    }
}
```

输出`2,1`、hello、String[]。闭合为int后Add的元素参数是int，ToArray结果是int[]；闭合为string后对应string/string[]。`T temp`是值类型或引用类型值的局部变量，其实际复制语义由类型实参决定，T本身不是保存“类型对象”的普通变量。

原正式答和思考区的三行表完全相同，只合并这一对重复表。

| 原说明 | 代码对应及准确边界 |
| --- | --- |
| 类名后<T> | 声明List<T>等类型参数，不是创建对象 |
| T是类型参数 | 使用时由int/string等类型实参构造类型 |
| 可在数据类型位置使用T | 参数、返回值、数组、字段、局部等允许位置；仍受语法和约束规则限制 |

“凡能写类型名的地方都能写T”是这里帮助理解常见使用位置的简化说法，不能据此写`class Bad<T> : T`或无约束`Nullable<T>`；基类、可空值类型等有另外的规则。T能够写在某位置，也不代表它自动拥有算术、比较或构造能力。

<a id="c12-indexer"></a>
### 索引器的value为何是T

原追问专门要求看懂this。索引器是C#成员，编译器识别并降低为访问器及相应元数据，并非“编译器不认识this[...]”。对于有get和set的`T this[int index]`，形状对应返回T的get_Item(int)和接受int索引、T value的set_Item；有的索引器只读，名称也可能被IndexerName修改，详见[第10章](第10章-属性.md#c10-accessor-calls)。

原MyList<T>只声明_array却没初始化，直接写`list[0]=10`会NRE。以下完整程序补构造器分配数组，保留int与string两个索引0场景。

```csharp
using System;
public class MyList<T> {
    private readonly T[] _array;
    public MyList(int length) { _array = new T[length]; }
    public T this[int index] {
        get { return _array[index]; }
        set { _array[index] = value; }
    }
}
class Program {
    static void Main() {
        var ints = new MyList<int>(1); ints[0] = 10; int x = ints[0]; Console.WriteLine(x);
        var strings = new MyList<string>(1); strings[0] = "hello";
        string s = strings[0]; Console.WriteLine(s);
    }
}
```

输出10和hello；非法索引由数组检查，负length等按数组创建规则失败。set内部的value是隐式参数，C#把value作为上下文关键字，其类型由索引器返回/元素类型T决定；int实例的value是int，string实例的是string。

原`public T get_Item(int index)`、`public void set_Item(int index,T value)`用于对齐参数与返回值，下面保留为**元数据形状示意**，不新增同名普通方法与真实索引器冲突，也不表示可绕过C#访问器调用限制。

```text
MyList<int>:    get_Item(int index) -> int
               set_Item(int index, int value) -> void
MyList<string>:get_Item(int index) -> string
               set_Item(int index, string value) -> void
```

接口也可声明索引器并由实现类型选择存储；这与接口不要求每个实例带字段不同，原IList<T>追问在新旧接口节继续展开。

<a id="c12-delivery"></a>
## “源代码保护”：不需要原.cs，不等于无法逆向

原追问“C++为什么不能发送编译产物”是上一轮绝对化说法造成的误解。C++当然可以交付.obj、.lib和DLL；差别在于消费者要以**库未预先提供的类型**实例化模板时，需要相应定义可供编译器处理。显式实例化可以把支持的特化编译交付。模板是有语言语义及类型检查的构造，不是C预处理宏的简单文本替换。

<a id="c12-dll-swap"></a>
### C#：库和客户端分别编译的Swap场景

第一份是**算法库源文件**，编译为Algorithm.dll交付给消费者。补上原缺失的Algorithm命名空间，使客户端`using Algorithm`与库对应；保留原IComparable<T>约束，说明它对单纯Swap算法其实多余，交换本身只用赋值。

```csharp
using System;
namespace Algorithm {
    public class Utils<T> where T : IComparable<T> {
        public static void Swap(ref T a, ref T b) {
            T temp = a; a = b; b = temp;
        }
    }
}
```

第二份是**独立客户端完整程序**，只引用已生成DLL编译，编译命令不包含库的.cs。

```csharp
using System;
using Algorithm;
class Program {
    static void Main() {
        int x = 1, y = 2; Utils<int>.Swap(ref x, ref y);
        string a = "Hello", b = "World"; Utils<string>.Swap(ref a, ref b);
        Console.WriteLine(x + "," + y);
        Console.WriteLine(a + "," + b);
    }
}
```

预期输出`2,1`、`World,Hello`。泛型定义和算法IL已在程序集里，消费者不必取得原源文件。JIT部署按需要生成或共享代码；Native AOT则在发布时处理所需代码，不能把所有现代.NET都说成运行时JIT。

“源代码保护”在此主要是分发不依赖源码，不是密码学保密。反编译可恢复算法逻辑，IL也能被工具分析或改写；混淆、原生编译会改变逆向成本，均非绝对不可恢复。闭源组件如原例提到的Newtonsoft.Json式消费方式，关键在程序集公开契约，不因泛型就自动保护知识产权。

### C++：消费者看到模板定义时实例化

这是**文件配对示例**。追加核验在本机D盘已有MSVC14.44.35207与Windows SDK10.0.26100.0下，按C++17编译八个原围栏文件及对应客户端；未安装工具。前期仅搜索PATH/C盘常见根未找到编译器，是搜索范围不足，现以实际四场景结果为准。[C++追加实测](整理记录/验证工作区/第12章/C++协调验证/核验说明.md)

```cpp
// Utils.h：模板定义对消费者可见
#pragma once
template <typename T>
void Swap(T& a, T& b) {
    T temp = a; a = b; b = temp;
}
```

```cpp
// YourProgram.cpp
#include "Utils.h"
#include <string>
#include <iostream>
int main() {
    int x = 1, y = 2; Swap(x, y);
    std::string a = "Hello", b = "World"; Swap(a, b);
    std::cout << x << ',' << y << '\n' << a << ',' << b << '\n';
}
```

具备复制/赋值能力的这两种类型分别实例化Swap；预期输出同前。模板支持特化、非类型模板参数等与C#泛型不同的表达能力，但“更灵活”不能自动推导所有任务更好，也不是要求库采用开源许可证。提供可见定义与授权公开源码是两回事。

<a id="c12-cpp-link"></a>
### 只声明模板，却未交付定义或所需特化的失败

原A.cpp/B.cpp独立翻译流程保留：各自编译为.obj，再由链接器组合。通常编译一个翻译单元不会自动查看另一个.cpp的模板定义；链接阶段寻找所需符号，而不是客户端编译器去.lib中找源定义。

```cpp
// Utils.h：只有声明
#pragma once
template <typename T> void Swap(T& a, T& b);
```

```cpp
// Utils.cpp：有定义，但没有调用或显式实例化
#include "Utils.h"
template <typename T>
void Swap(T& a, T& b) { T temp = a; a = b; b = temp; }
```

```cpp
// Main.cpp：这个翻译单元看不到模板定义
#include "Utils.h"
int main() { int x = 1, y = 2; Swap<int>(x, y); }
```

在这个场景，若库没有Swap<int>的具体实现，链接会缺相应符号；LNK2019是MSVC中可能出现的诊断名称，不是所有工具链共同错误码。不能说整个Utils.lib必然为空，只是这里没有生成消费者需要的模板实例。将定义移到可见头文件是一个方案；原“唯一方案”错误，下一例保留另一个。

<a id="c12-cpp-explicit"></a>
### 显式实例化：可以交付编译产物，但限定支持类型

保留原int和double两种预先支持的类型。以下**另一组交付文件**让模板定义留在库.cpp，消费者的头文件只有声明和extern模板声明。

```cpp
// Utils.h
#pragma once
template <typename T> void Swap(T& a, T& b);
extern template void Swap<int>(int&, int&);
extern template void Swap<double>(double&, double&);
```

```cpp
// Utils.cpp：编译进库，不必把这个源文件交给消费者
#include "Utils.h"
template <typename T>
void Swap(T& a, T& b) { T temp = a; a = b; b = temp; }
template void Swap<int>(int&, int&);
template void Swap<double>(double&, double&);
```

```cpp
// Main.cpp：链接到上述库
#include "Utils.h"
#include <iostream>
int main() {
    int x = 1, y = 2; Swap(x, y);
    double a = 1.5, b = 2.5; Swap(a, b);
    std::cout << x << ',' << y << '\n' << a << ',' << b << '\n';
}
```

预期输出`2,1`、`2.5,1.5`。消费者要用未预供的MyCustomClass特化时，这套有限分发不能自动提供它，需要定义或新增特化产物。这是有效的库设计选择，不是“C++勉强才能发二进制”。相同实例化在多个模块出现可被实现合并；MSVC还有相同COMDAT折叠，不能绝对说每翻译单元最终都保留重复机器码。[显式实例化](https://learn.microsoft.com/en-us/cpp/cpp/explicit-instantiation?view=msvc-170)、[函数模板实例化](https://learn.microsoft.com/en-us/cpp/cpp/function-template-instantiation?view=msvc-170)、[MSVC链接优化](https://learn.microsoft.com/en-us/cpp/build/reference/opt-optimizations?view=msvc-170)

| 灵活性 | 受CLR/C#类型系统和约束规则限制 | 有特化和非类型参数等；按任务判断取舍 |

| 信息处理 | 模板实例化有语义与类型检查，非宏文本替换 | 泛型元数据保留，按具体运行/发布模型构造与编译 |
| 产物形态 | 未使用模板未必生成实例；已实例化产生具体实现 | 组件包含泛型IL/元数据，部署可进一步原生编译 |
| 分发需求 | 生成未预供特化要定义；已提供特化可只链接产物 | 通常引用程序集即可使用其公开泛型算法 |
| 灵活性 | 特化等能力有自己的条件 | 类型系统和约束限定可用操作，能保证相应检查 |

<a id="c12-timer"></a>
## OperationTimer：开始计时、读取时间及GC次数

原追问给了完整OperationTimer。以下保留原字段、构造器顺序、Dispose格式及Collect/Wait/Collect三步，只补using，作为**完整类型片段**。

```csharp
using System;
using System.Diagnostics;
internal sealed class OperationTimer : IDisposable {
    private Stopwatch m_stopwatch;
    private String m_text;
    private Int32 m_collectionCount;
    public OperationTimer(String text) {
        PrepareForOperation();
        m_text = text;
        m_collectionCount = GC.CollectionCount(0);
        // 放在构造器最后，少计入本对象初始化工作
        m_stopwatch = Stopwatch.StartNew();
    }
    public void Dispose() {
        Console.WriteLine("{0} (GCs={1, 3}) {2}", m_stopwatch.Elapsed,
            GC.CollectionCount(0) - m_collectionCount, m_text);
    }
    private static void PrepareForOperation() {
        GC.Collect();
        GC.WaitForPendingFinalizers();
        GC.Collect();
    }
}
```

<a id="c12-timer-using"></a>
### using如何界定测量范围

方法体片段，DoSomething为需要测量的业务/测试方法：

```csharp
using (var timer = new OperationTimer("My Test")) {
    DoSomething();
}
```

using在正常结束或异常离开时经finally调用Dispose（构造成功的前提下）。构造器负责准备、保存GC基准和StartNew；Dispose读取Elapsed及GC差值并打印。原代码**没有Stop**，也没有释放任何非托管资源：IDisposable在这里借作结束回调，不代表运行时自动停止Stopwatch。重复调用Dispose会再次观察仍在运行的表；测量边界到读取Elapsed时，不含后续Console实际输出全过程。

<a id="c12-timer-gc"></a>
### Collect、等待终结器、再Collect各做什么

GC.Collect请求回收相应不可达对象，不清空托管堆，也不回收仍有根引用的对象。第一次回收可使待终结对象进入终结处理流程；WaitForPendingFinalizers等待正在等待处理的终结工作，不是又一次GC；第二次Collect可回收已经终结且仍不可达的对象，也可处理期间新产生的不可达对象。终结器可能复活对象，不能保证把所有待终结对象都清干净。

这三步试图减少测试前遗留状态的影响，没有排除测试过程中产生的GC，也不能保证纯运算耗时。它会改变堆代际和测试条件，不适合作为所有生产操作前的常规步骤。[GC.Collect](https://learn.microsoft.com/en-us/dotnet/api/system.gc.collect?view=net-10.0)、[等待终结器](https://learn.microsoft.com/en-us/dotnet/api/system.gc.waitforpendingfinalizers?view=net-10.0)

GC.CollectionCount(0)是第0代集合次数计数，用开始与结束值相减观察期间变化；原工具选择0代这一经常发生的集合指标，不是已分配字节数、全系统内存压力或每次暂停时长。Stopwatch.StartNew创建并启动表，Elapsed给TimeSpan；读取Elapsed不会自动停表。[GC计数](https://learn.microsoft.com/en-us/dotnet/api/system.gc.collectioncount?view=net-10.0)、[Elapsed](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.stopwatch.elapsed?view=net-10.0)

<a id="c12-legacy"></a>
## 泛型接口和非泛型接口为何并存

原问是：List<T>若只实现IList<T>，为什么不能当IList使用？它们是不同接口，IList<T>不继承IList，不能从“泛型版本”三个字自动推出旧接口转换。IEnumerable<T>却继承非泛型IEnumerable，具体继承关系须逐个看，不能说所有泛型/非泛型接口一律毫无关系。

<a id="c12-old-process"></a>
### OldClass.Process(IList)和真实List<DateTime>

以下完整程序保留原旧代码Count与新代码DateTime列表。真实BCL List<T>实现两类接口，调用**成功**；原标成失败的代码只有在“假设该类不实现IList”的条件下才失败，不能对实际List<DateTime>直接标编译错误。

```csharp
using System;
using System.Collections;
using System.Collections.Generic;
public class OldClass {
    public void Process(IList list) { Console.WriteLine(list.Count); }
}
class Program {
    static void Main() {
        var dates = new List<DateTime>();
        OldClass old = new OldClass(); old.Process(dates); // 输出0
        dates.Add(new DateTime(2000, 1, 1)); old.Process(dates); // 输出1
    }
}
```

这是“身兼两职”的具体库设计，不是所有泛型类都必须实现IList。例如只有IEnumerable<T>能力的类，不会自动获得IList随机访问接口。原动物/狗类比强调符合旧契约才能被接受；List<Dog>本身不是一只Dog，不能借元素Dog的继承关系获得集合接口。需要的是集合类型明确实现相应接口。

<a id="c12-reflection-list"></a>
### 运行时决定元素类型的反射例

完整程序保留原typeof(DateTime)、MakeGenericType、Activator及IList.Add(DateTime.Now)场景。

```csharp
using System;
using System.Collections;
using System.Collections.Generic;
class Program {
    static void Main() {
        Type type = typeof(DateTime);
        IList list = (IList)Activator.CreateInstance(typeof(List<>).MakeGenericType(type));
        list.Add(DateTime.Now);
        Console.WriteLine(list.Count);
        Console.WriteLine(list[0] is DateTime);
        try { list.Add("wrong"); }
        catch (ArgumentException) { Console.WriteLine("wrong element"); }
    }
}
```

输出1、True、wrong element。DateTime传给object形参时装箱，从IList取出值也是object表示；List<DateTime>仍保存DateTime元素，旧接口入口会检查对象是否兼容，不能把IList说成完全没有运行时类型检查。“未知T不能在源码直接写一个特定IList<T>变量”是这里用IList的便利原因，不等于反射、泛型辅助方法或动态方案绝对不能处理泛型接口。

<a id="c12-two-indexers"></a>
### T索引器与显式object索引器可以并存

原源码只给两个索引器，其余成员省略，不是完整IList实现。下面**完整教学类型**补上转发成员与存储，突出两个索引器的不同签名；后备BCL List<T>已经提供非泛型入口的类型检查。

```csharp
using System;
using System.Collections;
using System.Collections.Generic;
public class DualList<T> : IList<T>, IList {
    private readonly List<T> items = new List<T>();
    public T this[int index] { get { return items[index]; } set { items[index] = value; } }
    object IList.this[int index] {
        get { return ((IList)items)[index]; } set { ((IList)items)[index] = value; }
    }
    public int Count { get { return items.Count; } }
    public bool IsReadOnly { get { return false; } }
    bool IList.IsFixedSize { get { return false; } }
    bool ICollection.IsSynchronized { get { return false; } }
    object ICollection.SyncRoot { get { return ((ICollection)items).SyncRoot; } }
    public void Add(T value) { items.Add(value); }
    int IList.Add(object value) { return ((IList)items).Add(value); }
    public void Clear() { items.Clear(); }
    public bool Contains(T value) { return items.Contains(value); }
    bool IList.Contains(object value) { return ((IList)items).Contains(value); }
    public int IndexOf(T value) { return items.IndexOf(value); }
    int IList.IndexOf(object value) { return ((IList)items).IndexOf(value); }
    public void Insert(int index, T value) { items.Insert(index, value); }
    void IList.Insert(int index, object value) { ((IList)items).Insert(index, value); }
    public bool Remove(T value) { return items.Remove(value); }
    void IList.Remove(object value) { ((IList)items).Remove(value); }
    public void RemoveAt(int index) { items.RemoveAt(index); }
    public void CopyTo(T[] array, int index) { items.CopyTo(array, index); }
    void ICollection.CopyTo(Array array, int index) { ((ICollection)items).CopyTo(array, index); }
    public IEnumerator<T> GetEnumerator() { return items.GetEnumerator(); }
    IEnumerator IEnumerable.GetEnumerator() { return GetEnumerator(); }
}
```

经DualList<int>表达式读取索引器得到int，经IList表达式得到object；通过显式接口实现选择同名成员的不同契约。这种转发不要求维护两份元素数组，却需满足两套接口成员，增加适配和维护成本。

| 接口类型 | 角色 | 历史入口 | 优点 | 条件/代价 |
| --- | --- | --- | --- | --- |
| IList<T> | 以元素类型工作的集合契约 | .NET2.0起 | 泛型入口提供静态类型，值元素路径可避装箱 | 不等于IList；未知类型时仍有反射等方法，不是绝对不能用 |
| IList | 旧接口及object适配入口 | .NET1.0起 | 与要求旧接口的API互操作，反射时方便 | 值类型经object入口可装箱，错误元素主要在运行时检查 |

<a id="c12-open-closed"></a>
## 开放类型、封闭类型与泛型类型不是同一维度

原“开发类型”按上下文是“开放类型”。“泛型”描述带类型参数的类型定义及其构造，“开放”描述是否仍含未绑定类型参数。并不是所有封闭类型都为泛型，也不是所有开放类型都IsGenericType为true：包含开放T的数组类型也开放。

`typeof(List<>)`和`typeof(Dictionary<,>)`取得未绑定泛型定义的Type对象；`List<int>`、`Dictionary<string,int>`、`Nullable<DateTime>`是封闭构造。`Dictionary<string,T>`仍可开放，却不是generic type definition，所以“构造类型”不等于“已经完全封闭”。

| 名称 | 主要判断 | 是否仍含未绑定参数 | 能否创建实例 | 原例 |
| --- | --- | --- | --- | --- |
| 泛型类型 | IsGenericType等泛型性质 | 视构造而定 | 还须满足具体创建条件 | List<T>、List<int> |
| 开放类型 | ContainsGenericParameters为true | 是 | 反射不能直接创建含未绑定参数的实例 | List<>、开放上下文List<T>、部分构造/含T数组 |
| 封闭类型 | ContainsGenericParameters为false | 否 | 此条件必要，但还需可创建的具体类型/构造器 | List<int>可new；封闭接口或抽象类不可直接new |

原“List<T>在源码不能new”错误：泛型方法执行时已有具体类型实参，下面完整程序可以编译运行。

```csharp
using System;
using System.Collections.Generic;
class Program {
    static List<T> Make<T>(T item) {
        var result = new List<T>(); result.Add(item); return result;
    }
    static void Main() { Console.WriteLine(Make(7)[0]); }
}
```

输出7。`new List<>()`没有这种普通实例创建语法，`new List<T>()`在合法泛型上下文却可以。反射拿到包含未知参数的开放Type不能调用Activator创建实例，是另一种情况。

<a id="c12-reflection-flags"></a>
### 反射六个标志与部分构造的边界

完整程序保留原两Type、各三个属性输出，再补部分构造与T数组以区分概念。

```csharp
using System;
using System.Collections.Generic;
class G<T> { }
class Program {
    static void Main() {
        Type t1 = typeof(List<>);
        Console.WriteLine(t1.IsGenericType);
        Console.WriteLine(t1.IsGenericTypeDefinition);
        Console.WriteLine(t1.ContainsGenericParameters);
        Type t2 = typeof(List<int>);
        Console.WriteLine(t2.IsGenericType);
        Console.WriteLine(t2.IsGenericTypeDefinition);
        Console.WriteLine(t2.ContainsGenericParameters);
        try { Activator.CreateInstance(t1); }
        catch (ArgumentException) { Console.WriteLine("open type cannot be instantiated"); }
        Type parameter = typeof(G<>).GetGenericArguments()[0];
        Type partial = typeof(Dictionary<,>).MakeGenericType(typeof(string), parameter);
        Console.WriteLine(partial.IsGenericTypeDefinition + "," + partial.ContainsGenericParameters);
        Type array = parameter.MakeArrayType();
        Console.WriteLine(array.IsGenericType + "," + array.ContainsGenericParameters);
    }
}
```

前六行为True、True、True、True、False、False；之后为开放类型失败说明、`False,True`、`False,True`。IsGenericTypeDefinition=false表示不是泛型定义，不表示某个对象已经new出来。程序集保留泛型TypeDef/MethodDef及参数信息，加载封闭类型时取得对应运行时类型结构，不是在DLL里重新写一份TypeDef或生成一份源文件。

原蛋糕口味模具类比：泛型是模具这一类设计，开放时口味未填，封闭时填巧克力/某类型；封闭图纸才适于创建对应对象，但图纸还可能是接口/抽象设计，不能保证每张封闭图纸都能住人。原“图纸与填坑房子”类比也要区分构造了类型和创建了对象，封闭类型本身仍是类型，不是对象实例。

思考区另有数学公式类比：T像尚未代入的未知数，填入int等类型实参使相应类型闭合；代入形成具体类型这一动作不等于执行new创建对象，也不能把类型参数当普通数值变量。

### 静态字段和静态构造器按具体封闭类型独立

原MyClass<T>静态构造器Int32、String及第三次int的场景，补一个计数字段观察类型独立性。完整程序：

```csharp
using System;
class MyClass<T> {

    static MyClass() { Console.WriteLine(typeof(T).Name); }
```

<a id="c12-alias-identity"></a>
### using别名与派生DateTimeList是不同选择

原章概览提醒DateTimeList同一性。下面两个**独立完整程序**保留对照：别名只改源码名称，不产生新类型；派生声明产生新类型，不能当成纯别名。

```csharp
using System;
using DateTimeList = System.Collections.Generic.List<System.DateTime>;
class Program {
    static void Main() {
        Console.WriteLine(typeof(DateTimeList) == typeof(System.Collections.Generic.List<DateTime>));
    }
}
```

输出True。

```csharp
using System;
using System.Collections.Generic;
class DateTimeList : List<DateTime> { }
class Program {
    static void Main() {
        Console.WriteLine(typeof(DateTimeList) == typeof(List<DateTime>));
        List<DateTime> list = new DateTimeList(); // 派生对象能作为基类使用
        Console.WriteLine(list is DateTimeList);
    }
}
```

输出False、True。需要名称简写时别名合适；需要扩展行为时派生可能有自己的用途，不把“产生新类型”直接判成任何设计都错误。

<a id="c12-sharing"></a>
## JIT代码共享缓解代码爆炸，不改变泛型类型身份

原问引用经典CLR说明：使用某方法/类型实参组合时，JIT生成相应代码，多个组合可能增加本机代码与工作集；重复使用同一组合可复用已生成实现，相容的引用类型实例化还能共享代码。这里讲的是方法代码，不是每new一个List就复制一份机器码，也不是每个程序集另建一套同一类型定义。

<a id="c12-additem"></a>
### AddItem<T>的三个类型及重复调用

完整程序保留原int5、string a、DateTime和后来int10四次调用。输出观察的是元素，不用它来伪证明机器码地址。

```csharp
using System;
using System.Collections.Generic;
class Program {
    static void AddItem<T>(List<T> list, T item) { list.Add(item); }
    static void Main() {
        var ints = new List<int>(); AddItem(ints, 5); AddItem(ints, 10);
        var strings = new List<string>(); AddItem(strings, "a");
        var dates = new List<DateTime>(); AddItem(dates, new DateTime(2000, 1, 1));
        Console.WriteLine(string.Join(",", ints));
        Console.WriteLine(strings[0]); Console.WriteLine(dates[0].Year);
    }
}
```

输出5,10、a、2000。经典AppDomain上下文里，两个程序集都使用同一定义的List<DateTime>，不因调用者程序集不同就必然为同一实现重复JIT。这里要求相同类型身份和相应加载上下文；不同定义/加载身份不可凭同名类型混合。

<a id="c12-reference-sharing"></a>
### string、Stream和object相容实例化的共享模型

引用槽保存对象引用，32位进程通常4字节、64位通常8字节；变量可以在寄存器、栈、对象或数组中，不能说引用变量都必在栈上。共享实现通过泛型上下文/字典获得确切类型相关信息，不是把类型当成普通object后丢弃全部类型检查。`List<string>`与`List<Stream>`仍有不同类型身份、数组元素类型与静态状态。

以下保留原代码仓库**概念图**，0x01等是示意编号，不是反汇编或实测地址。

原另一组值类型例是List<int>与List<Guid>：经典CLR通常分别为相应值表示生成适用代码，和List<int>/List<DateTime>或List<Int32>/List<Double>是不同原实例，保留此处；同为值类型不表示布局与操作完全相同，也不把典型特化扩大成所有现代优化绝不共享的保证。

```text
典型兼容代码仓库
示意编号  方法代码模型      使用者
0x01      List<RefType>     List<string>、List<Stream>、List<object>、List<MyClass>
0x02      List<Int32>       List<int>
0x03      List<DateTime>    List<DateTime>
```

原类型片段的两组对照仍保留：

```csharp
// 方法体片段；using System、System.IO、System.Collections.Generic
List<Stream> s1 = new List<Stream>();

List<Int32> i1 = new List<Int32>();
List<Double> d1 = new List<Double>();
```

经典共享策略下，相容引用类型的Add等实现可共享canonical代码，int/double的值表示通常分别实例化；并非把Stream对象和String对象本身当成完全同一布局，只是处理它们的引用表示有相容性。[CoreCLR共享泛型设计](https://github.com/dotnet/runtime/blob/main/docs/design/coreclr/botr/shared-generics.md)、[类型加载与身份](https://github.com/dotnet/runtime/blob/main/docs/design/coreclr/botr/type-loader.md)

### 值类型大小相同也不代表代码语义相同

原例保留int4字节、long8字节、DateTime8字节、两个int字段的MyStruct通常8字节的比较；具体struct布局仍看字段、布局属性及平台。大小不同会影响元素步长和复制；int与uint同4字节，却有有符号/无符号语义区别。这支持原书值类型通常分别生成代码的解释，不能只比较大小。

原`T a=1; T b=2; if(a<b)`没有约束，不是合法泛型C#。下面用具体类型保留signed/unsigned区别，完整程序：

```csharp
using System;
struct MyStruct { public int x, y; }
class Program {
    static void Main() {
        int signed = -1; uint unsigned = unchecked((uint)signed);
        Console.WriteLine(signed < 2);
        Console.WriteLine(unsigned < 2U);
        Console.WriteLine(sizeof(int) + "," + sizeof(uint));
    }
}
```

输出True、False、4,4。原CMP说法仅为指令示意：x86同宽度CMP本身可相同，后续按符号/无符号解释条件码和分支会不同；不能声称这段已产生两条特定不同的CMP，或任意算法在相同值类型宽度下绝无共享优化。

| 特性 | 引用类型实参的典型模型 | 值类型实参的典型模型 |
| --- | --- | --- |
| 存储内容 | 引用表示，槽大小通常固定 | 值表示，大小与内容由类型确定 |
| 复制 | 复制引用，不复制整个所指对象 | 复制值；结构可含引用字段，不是深拷贝对象图 |
| CPU处理 | 引用表示相容，类型相关行为由上下文等处理 | 布局、调用/比较等语义可不同 |
| 代码共享 | 经典CLR支持相容实例化共享 | 经典CLR常分别实例化具体值类型 |
| 代码量风险 | 共享降低重复代码，仍有类型/字典等成本 | 更多不同组合可能增加代码，不是每种应用都‘严重’ |

### 历史缓存叙述与现代JIT/AOT的边界

“同一组合只编译一次”说明经典普通运行中的复用策略，不能绝对化成所有现代方法一生只能有一个代码版本。分层编译、动态PGO、预编译代码与运行时优化可改变生成时机或版本；不能以一个入口指针相等/不等证明所有泛型机器码体完全相同。Native AOT发布时处理所需实例化，不在运行时JIT，泛型值实例化会影响原生二进制大小；实际策略要看运行时与部署版本。[Native AOT说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/)

原定制西装类比：算法IL像布料，类型是身材，编译器像裁缝；同尺码复用已有款，相容引用表示像可共用某基础版。跨程序集仓库类比强调同身份组合不因不同顾客就重新做。值类型如不同裁剪尺寸/操作需求通常要单独款式；现实优化也可改制，不能把类比当性能与代码量定律。

<a id="c12-func"></a>
## Func的声明和使用：普通BCL类型，没有自动推断变型标记

原问“Func不是内置委托吗，直接public Func<in T,out TResult>不行吗”混合了类型定义和成员声明。System.Func是类库预定义的委托类型，并非C#编译器特殊提供的简写。原书展示的完整delegate定义属于**C#源语言声明**，不是IL语法；其变型标记随后保存为元数据。

```text
// 框架类型声明的C#形状；使用者不在自己的System命名空间重新定义它
public delegate TResult Func<in T, out TResult>(T arg);
```

使用现成类型时写`Func<int,string>`或在合法泛型上下文写`Func<T,TResult>`，不重新声明in/out。`public Func<T,TResult> myFunc;`可以是合法公开字段；错误不在public或“委托已定义不能再出现”，而在把类型参数声明标记放到类型实参使用位置。自己在其他命名空间定义不同委托也合法。

<a id="c12-func-field"></a>
### 错误字段与正确字段、自己定义的新委托

正确**类型片段**：

```csharp
using System;
class Holder<T, TResult> { public Func<T, TResult> myFunc; }
public delegate TResult MyFunc<in T, out TResult>(T arg);
```

原字段反例及另一MyDelegate使用处反例保留为非法语法示意，不能当作合法类型表达式。

```text
public Func<in T, out TResult> myFunc; // 反例：使用处没有这种in/out语法
MyDelegate<out T> d;                  // 同一类错误，out不是这里的类型实参
```

原`delegate T MyDelegate<out T>();`是合法的**定义**，在泛型上下文用`MyDelegate<T> d`是合法**使用**。接口与委托的泛型参数定义可声明variance；普通泛型class参数不能照此声明in/out。这不是where类型约束，编译器也不会因T出现在参数或返回值中而自动给未标注的类型推断in/out。

| 原两行对照 | 准确含义 | 场景 |
| --- | --- | --- |
| Func<T,TResult> | 使用/构造已有委托类型；不是自动省略IL的语法糖 | 字段、局部、参数等类型位置 |
| `delegate TResult Func<in T,out TResult>(T arg)` | 类型定义的C#形状，声明类型参数的变型方向 | 类库定义及学习该契约 |

原下一张三行表比较允许动作，用途不同，保留如下。

| 行为 | 代码形状 | 是否允许 | 含义 |
| --- | --- | --- | --- |
| 定义委托 | `delegate T MyDelegate<out T>();` | 允许 | 在类型参数定义上提供变型标记 |
| 使用委托 | `MyDelegate<out T> d;` | 不允许 | 不能把variance声明标记写成类型实参 |
| 使用委托 | `MyDelegate<T> d;` | 合法泛型上下文允许 | 根据已定义契约使用 |

<a id="c12-func-conversions"></a>
### GetString(object)及两个不同转换

完整程序保留原object输入、string输出及分开的参数/返回值转换，另外保留章概览的ArgumentException→Exception组合例。

```csharp
using System;
class Program {
    static string GetString(object o) { return o.ToString(); }
    static ArgumentException Error(object o) { return new ArgumentException(o.ToString()); }
    static void Main() {
        Func<object, string> getStringFunc = GetString;
        Func<string, string> func1 = getStringFunc; // 输入逆变：通用工具可处理string
        Func<object, object> func2 = getStringFunc; // 输出协变：string可当object结果
        Console.WriteLine(func1("Hello")); Console.WriteLine(func2(123));
        Func<object, ArgumentException> original = Error;
        Func<string, Exception> combined = original;
        Console.WriteLine(combined("problem").GetType().Name);
    }
}
```

输出Hello、123、ArgumentException。这是委托对象的变型转换，不复制回调体；GetString对null输入会因ToString调用而NRE，本程序传非null值。

原正式答在文字中写反了两个方向，虽后面的func1/func2代码正确，仍应纠正：协变例是**Func<string>→Func<object>**，不是相反；这个单类型参数Func<T>是无参、返回T的委托，不能拿它表示输入参数逆变。输入逆变可用Action<object>→Action<string>或上面的双参数Func例；只能处理string的工具不能被要求处理任意object。

<a id="c12-myfunc-invariant"></a>
### 自定义MyFunc不标注时，不自动获得变型

以下两个命名空间允许保留原同名不变/变型定义并独立比较，**完整程序**：

```csharp
using System;
namespace Fixed {
    public delegate TResult MyFunc<T, TResult>(T arg);
}
namespace Variant {
    public delegate TResult MyFunc<in T, out TResult>(T arg);
}
class Program {
    static string GetString(object item) { return item.ToString(); }
    static void Main() {
        Fixed.MyFunc<object, string> fixedFunc = GetString;
        // Fixed.MyFunc<string, string> bad = fixedFunc; // 反例：不变型
        Variant.MyFunc<object, string> variantFunc = GetString;
        Variant.MyFunc<string, object> flexible = variantFunc;
        Console.WriteLine(flexible("Hello"));
    }
}
```

输出Hello。C# 4/.NET 4背景支持泛型接口/委托的变型声明，不是原答所称C# 2即支持此声明语法。旧的委托方法组签名兼容是另一个问题，不能混算。现代Roslyn以`/langversion:3`消费.NET10已有Func变型元数据的验证实际接受；直接声明MyFunc的in/out在模式3报CS8024、模式4成功。这个现代兼容模式不等原C# 3编译器及其BCL环境，不据前一个观察反推历史版本。

### 原身份证、图纸、模具、车辆与出生证明类比

“日常口语与官方身份证”可对应使用类型名与查看完整定义，不能解释成前者是编译器隐藏了一半IL。图纸/汽车类比强调定义约定和按约定使用：Func能做相应转换，是类库定义带标记，不是编译器看每个回调后另造规则。

<a id="c12-enumeration"></a>
## 集合变型：元素引用转换和装箱不同

原连续几轮追问把“值类型不能变型”“两个ProcessCollection”和“Current为何in”混在一起。先固定方向：协变保持类型关系方向，例如IEnumerable<string>→IEnumerable<object>；逆变反转泛型参数方向，例如IComparer<Animal>→IComparer<Dog>。不能因对象被传进Count的方法参数，就把一个生产元素的接口改成逆变。

string→object引用转换仍引用原对象，不为了这次转换复制整个字符串。DateTime→object通常需装箱复制值到盒中；装箱不是这里的隐式引用变型转换。这是规定的类型安全规则，不能只用“零成本所以允许、花钱所以禁止”当完整语言定义或特定性能保证。[泛型协变与逆变](https://learn.microsoft.com/en-us/dotnet/standard/generics/covariance-and-contravariance)

<a id="c12-variance-values"></a>
### IEnumerable<string>允许，IEnumerable<DateTime>不能直接转object版

完整程序保留原引用/值序列正反对照，补显式装箱转换方案说明限制的准确范围。

```csharp
using System;
using System.Collections.Generic;
using System.Linq;
class Program {
    static void Main() {
        IEnumerable<string> strings = new List<string> { "hello" };
        IEnumerable<object> objects = strings;
        foreach (object o in objects) Console.WriteLine(o);
        IEnumerable<DateTime> dates = new List<DateTime> { new DateTime(2000, 1, 1) };
        // IEnumerable<object> bad = dates; // 反例：不通过值类型变型转换
        IEnumerable<object> boxed = dates.Cast<object>();
        foreach (object o in boxed) Console.WriteLine(((DateTime)o).Year);
    }
}
```

输出hello、2000。Cast<object>是显式选择的逐元素object表示路径，不是原序列免费获得变型；可有装箱/迭代成本。`IEnumerable<out T>`仍可构造IEnumerable<int>或IEnumerable<DateTime>，只是不能用这一变型关系把值实参换成object。DateTime属于Object类型系统并不表示DateTime→object是引用转换。

原塑料/乐高类比保留：引用类型像编号指向同一积木，更换观察标签不把积木复制；值像具体塑料块，装进礼品盒要产生object表示。原`List<Dog>→List<Animal>`例必须改正：List<T>是不变型，该转换不合法；可通过IEnumerable<Dog>→IEnumerable<Animal>只读产出协议观察。不能以积木标签类比放宽可写List，否则有人可能往“Dog列表”写入非Dog的Animal。

<a id="c12-processcollection"></a>
### 两个ProcessCollection及未使用T的原式

原引文第二式为`ProcessCollection<T>(IEnumerable<object> collection)`，它**语法可以合法**，只是T未用于参数，不能靠输入推断，也没有解决List<DateTime>转换问题；不能简单称它编译必错或声称未经核定的原书必故意如此。真正匹配元素类型的是IEnumerable<T>。

完整程序保留两种方法职责，并在不同类中避免同名重载导致示例观察被改变。

```csharp
using System;
using System.Collections.Generic;
class ObjectVersion {
    public static int ProcessCollection(IEnumerable<object> collection) {
        int count = 0; foreach (object item in collection) count++; return count;
    }
    public static int UnusedType<T>(IEnumerable<object> collection) {
        return ProcessCollection(collection);
    }
}
class GenericVersion {
    public static int ProcessCollection<T>(IEnumerable<T> collection) {
        int count = 0; foreach (T item in collection) count++; return count;
    }
}
class Program {
    static void Main() {
        Console.WriteLine(ObjectVersion.ProcessCollection(new List<string> { "hello" }));
        // ObjectVersion.ProcessCollection(new List<DateTime>()); // 反例
        Console.WriteLine(GenericVersion.ProcessCollection(new List<string> { "hello" }));
        Console.WriteLine(GenericVersion.ProcessCollection(new List<DateTime> { DateTime.Now }));
        Console.WriteLine(ObjectVersion.UnusedType<int>(new List<string> { "hello" }));
    }
}
```

输出四个1。第一个方法不是泛型方法，但参数IEnumerable<object>依然是泛型接口；能接引用协变序列，也能接显式构造的object序列（其中可有已装箱值），不能概括成“只能处理引用类型值”。泛型方法从元素接口推断T，可接受string和DateTime，不为了遍历元素而统一转为object。迭代器本身若为值类型再转接口，仍可能有另一种装箱，不能宣称所有泛型遍历完全零分配。

非泛型方法没有方法类型实参组合这一维度，经典JIT通常复用它本身的实现，并非因参数泛型实参object而发生“引用类型方法实例化共享”。泛型版本有多个T组合，经典相容引用共享和值类型专门代码的讨论适用；它不是必然“效率不够优”的方案，类型安全、数据表示和代码体积各要按负载判断。

原逻辑链图重排为正确条件：

```text
隐式泛型变型转换要求相应引用转换/安全条件
DateTime -> object为装箱，不提供 IEnumerable<DateTime> -> IEnumerable<object> 变型
  Object参数版本：可接相应引用序列/显式object表示序列
  Generic参数版本：可保留DateTime元素类型，考虑具体JIT/AOT代码成本
按需要选择；不据此统计‘90%场景都有值类型’或判变型整体无用
```

原书表达的是对限制实用性的个人评价，不把评价扩写成“90%通用集合都遇值类型”的统计事实。引用序列API、比较器、回调等仍有变型用途。

### Current输出T，真实IEnumerator<T>是out

原Q15/16及辅助章节摘录出现`IEnumerator<in T>`并返回`T Current {get;}`，这不合法。标准BCL声明是out T，并继承IDisposable及非泛型IEnumerator，**不是继承IEnumerable**。[IEnumerator<T>官方定义](https://learn.microsoft.com/en-us/dotnet/api/system.collections.generic.ienumerator-1?view=net-10.0)

```text
// BCL接口C#形状
public interface IEnumerator<out T> : IDisposable, System.Collections.IEnumerator {
    T Current { get; }
}
// 原反例，非可用教学接口
public interface BadEnumerator<in T> {
    T Current { get; } // 反例：CS1961，逆变T在这里输出
    bool MoveNext();
}
```

Framework与.NET10编译器均拒绝原逆变getter。跳过C#编译器，Reflection.Emit直接把T标成Contravariant再定义返回T的getter，两个运行时都在CreateType抛TypeLoadException。它不是“C#为了好看额外限制，但CLR只要觉得安全就允许”的例外。该实验只证明所测运行时对这个具体不安全声明的检查，CLI标准与源语法仍分别引用。

原Q17又声称这是Jeff在书p326故意写的假代码，并编出整段“原文”。现存源码/图片并未证明这段书页与作者意图，辅助摘录含错误也不构成证明。正文保留原错误作为对照，取消未经依据的页码、假例动机与“CLR允许”解释；不臆断未提供的纸书页面正确式。

<a id="c12-count-enumerable"></a>
### Count接收序列：Grant、Grant/Alice两个原场景

完整程序保留只一个Grant以及Grant/Alice两个不同数组输入。

```csharp
using System;
using System.Collections.Generic;
class Program {
    static int Count(IEnumerable<object> collection) {
        int count = 0; foreach (object obj in collection) count++; return count;
    }
    static void Main() {
        Console.WriteLine(Count(new[] { "Grant" }));
        string[] names = { "Grant", "Alice" };
        Console.WriteLine(Count(names));
    }
}
```

输出1、2。string[]提供IEnumerable<string>，其协变契约可用于IEnumerable<object>视图；不需要先把它赋给object[]。数组自身的string[]→object[]协变是另一个机制，若经object[]视图写入非string对象会在运行时受到数组存储检查，不能从这里推导可任意写入。

foreach在相应泛型接口路径中取得IEnumerator<object>，MoveNext后读Current；实际还会按规则释放可释放的枚举器。原while片段只是访问步骤示意，不包含完整清理协议。IEnumerator<string>→IEnumerator<object>沿元素string→object同方向，属于**协变**，不是逆变；Count是消费者不改变被消费枚举器的生产契约。

原巧克力/糖果类比保留两个角色：能产高级巧克力的生产者可满足产普通糖果的要求（协变）；能包装普通糖果的机器也能包装高级巧克力（逆变）。不是“Count参数里接巧克力”就使生产者变为逆变。万能插座两脚输入/5V输出的类比也须先明确是消费还是生产哪类对象，不能据插头数与电压直接推导类型兼容。

<a id="c12-count-enumerator"></a>
### Count接收枚举器，以及数组GetEnumerator的真实返回类型

Q17还给了接收IEnumerator<object>的不同Count和泛型Count<T>。以下完整程序保留这两个方法，及a/b、DateTime.Now的数组场景；调用方用using负责枚举器寿命。

```csharp
using System;
using System.Collections.Generic;
class Program {
    static int Count(IEnumerator<object> enumerator) {
        int count = 0;
        while (enumerator.MoveNext()) {
            object obj = enumerator.Current; count++;
        }
        return count;
    }
    static int CountTyped<T>(IEnumerator<T> enumerator) {
        int count = 0;
        while (enumerator.MoveNext()) {
            T item = enumerator.Current; count++;
        }
        return count;
    }
    static void Main() {
        string[] names = { "a", "b" };
        using (IEnumerator<string> e = ((IEnumerable<string>)names).GetEnumerator())
            Console.WriteLine(Count(e)); // 枚举器自身协变
        using (IEnumerator<string> e = ((IEnumerable<string>)names).GetEnumerator())
            Console.WriteLine(CountTyped<string>(e));
        DateTime[] dates = { DateTime.Now };
        using (IEnumerator<DateTime> e = ((IEnumerable<DateTime>)dates).GetEnumerator())
            Console.WriteLine(CountTyped<DateTime>(e));
        // CountTyped<string>(names.GetEnumerator()); // 反例：普通数组方法返回非泛型IEnumerator
    }
}
```

输出2、2、1。原直接`Count<string>(new string[]{...}.GetEnumerator())`/日期同式不兼容泛型枚举器参数，须经IEnumerable<T>取得对应枚举器。`IEnumerator<T>`的out独立定义保证它的协变，`IEnumerable<T>.GetEnumerator()`返回这个类型，不能说是IEnumerable的标记自动把一个非法in枚举器“带成out”。

<a id="c12-producer-consumer"></a>
### Animal/Dog生产者与IComparer消费者的正反方向

Q17思考区有与Current解释不同的两个角色例，保留为完整程序：

```csharp
using System;
using System.Collections.Generic;
class Animal { }
class Dog : Animal { }
class Program {
    static void Main() {
        Func<Dog> dogProducer = () => new Dog();
        Func<Animal> animalProducer = dogProducer; // 输出协变
        IComparer<Animal> animalComparer = Comparer<Animal>.Create((a, b) => 0);
        IComparer<Dog> dogComparer = animalComparer; // 输入逆变
        // IComparer<Animal> bad = dogComparer; // 反例：方向相反
        Console.WriteLine(animalProducer().GetType().Name);
        Console.WriteLine(dogComparer.Compare(new Dog(), new Dog()));
    }
}
```

输出Dog、0。需要Animal生产者时，能产Dog的对象满足要求；需要处理Dog的比较器时，能处理所有Animal的比较器满足要求。`F<Dog>→F<Animal>`是协变方向，`G<Animal>→G<Dog>`是逆变方向；不能将“目标元素更宽泛”定义为逆变。

<a id="c12-variance-composition"></a>
### 输入/输出口诀是单层简化，不能取代变型安全规则

对直接出现的T，返回T/get T是产出，普通参数T/set T是消费。实际规范还检查嵌套接口/委托的variance组合，不能把原“out只能出现在返回值，凡输入都绝对禁止”当完整规则。以下类型片段在C# 4+可用：

```csharp
using System;
interface IProducer<out T> {
    T Get();
    void SendTo(Action<T> consumer); // Action的逆变参数参与方向组合
}
```

Action<T>作为方法输入时组合了相应反向关系，外层out T仍可满足安全规则；这与“直接返回in T的Current”完全不同。声明不加in/out也可以是合法但不变型的接口；建议可用时选择变型，不表示每个接口必须标记。[变型接口设计](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/concepts/covariance-contravariance/creating-variant-generic-interfaces)、[规范变型安全条件](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/interfaces#19232-variance-safety)

<a id="c12-ref-variance"></a>
## ref/out形参的T要求不变型，和类型参数out不同

原多个反例指向同一规则，但有不同变量场景：把object赋进原string槽、把Animal赋进原Dog槽。它们都说明通过引用地址更新变量时不能像按值传递一样放宽类型。

```text
// 反例：两运行时对应C#编译均拒绝CS1961
delegate void SomeDelegate<in T>(ref T t);
delegate void SomeDelegate<out T>(out T t);
```

普通ref参数可读可写，out参数在C#中须先写后读，不能把out简单说成“方法一进来就能双向读取”。但二者都是按引用地址传递，声明泛型变型时涉及它们的T必须不变型。类型参数的`out T`声明协变，方法形参的`out T value`声明输出参数，语法位置与规则不同。

<a id="c12-ref-animal"></a>
### MakeAnimalBigger(ref Animal)不能绑定RefAction<Dog>

以下完整程序用合法不变型RefAction保留原场景，并把危险绑定标成反例；原`RefAction<in T>`声明本身已经不合法，不能跳过这一步声称危险代码实际运行。

```csharp
using System;
delegate void RefAction<T>(ref T obj);
class Animal { }
class Dog : Animal { }
class Program {
    static void MakeAnimalBigger(ref Animal a) { a = new Animal(); }
    static void Main() {
        Dog d = new Dog();
        // RefAction<Dog> bad = MakeAnimalBigger; // 反例：ref类型不能这样绑定
        Animal value = d;
        RefAction<Animal> action = MakeAnimalBigger;
        action(ref value);
        Console.WriteLine(value.GetType().Name);
        Console.WriteLine(d.GetType().Name);
    }
}
```

输出Animal、Dog。value是独立Animal变量槽，修改它不把d变成Animal。若容许方法将d的Dog槽当ref Animal修改，就可能安装非Dog的Animal；同理，要求ref string的方法不能把该槽开放成任意ref object写入new object。“狸猫换太子”类比描述的是这个被类型检查阻止的情形，不是合法程序中已发生的灾难。

<a id="c12-printer"></a>
### PrintString与PrintAnything：原所谓可编译方向实际相反

原一例先用不变型PrintDelegate<T>配PrintString打印Hello，后例改in T，却把只处理string的printString传给要打印Hello和123的PrintAnything，声称可编译。后者不安全也不通过编译。以下完整程序保留两种声明、两种用途及原失败调用，给出正确复用方向。

```csharp
using System;
namespace Fixed {
    public delegate void PrintDelegate<T>(T item);
}
namespace Variant {
    public delegate void PrintDelegate<in T>(T item);
}
class Program {
    static void PrintString(Fixed.PrintDelegate<string> printer) { printer("Hello"); }
    static void PrintStringVariant(Variant.PrintDelegate<string> printer) { printer("Hello"); }
    static void PrintAnything(Variant.PrintDelegate<object> printer) {
        printer("Hello"); printer(123);
    }
    static void Main() {
        PrintString(text => Console.WriteLine(text));
        Variant.PrintDelegate<object> printObject = item => Console.WriteLine(item);
        PrintStringVariant(printObject); // 能处理object者也可处理string
        PrintAnything(printObject);
        Variant.PrintDelegate<string> printString = text => Console.WriteLine(text);
        // PrintAnything(printString); // 反例：string工具不能处理123
    }
}
```

输出Hello、Hello、Hello、123。已有不变型PrintDelegate<object>不能隐式转换成PrintDelegate<string>；可以重新写一个lambda得到另一个类型的委托，但那不是变型转换。保持输入契约是“通用工具可代替更具体工具”，不是反过来。

| 原场景 | 声明关键字 | 含义 | 保留的示例 |
| --- | --- | --- | --- |
| 产出/return | out | 协变 | 产Dog的Func可当产Animal的Func |
| 输入/param | in | 逆变 | 处理Animal的Action/比较器可处理Dog |
| ref地址输入输出 | 不标variance | 不变型 | RefAction<T>的按引用T须匹配；out形参也按相应不变规则 |

原鼓励给合适接口/委托标in/out，是为了增加满足安全条件的互换用途；不是编译器自动推断，也不是无条件为每个泛型参数加标签。

<a id="c12-members"></a>
## 成员使用外围T，与成员自己声明类型参数不同

原12.7追问要求逐项举例：属性、索引器、事件、操作符、构造器和终结器不能在C#声明自己的类型参数列表，却可以在泛型类型中使用外围T。普通方法可以另有自己的TResult；原思考区先称Add不能另有参数、随后自我纠正，最终以方法可自有参数为准。

<a id="c12-outer-members"></a>
### 同一MyClass<T>中可用外围参数的不同成员

完整类型片段兼容C# 5，保留属性、索引器、事件、构造器、终结器和普通泛型方法。原自动索引器`this[int index] {get;set;}`不合法，此处用实际数组存储。

```csharp
using System;
public class MyClass<T> {
    private readonly T[] items;
    public MyClass(T value) { items = new T[] { value }; }
    public T MyProp { get; set; }
    public T this[int index] {
        get { return items[index]; } set { items[index] = value; }
    }
    public event Action<T> MyEvent;
    public TResult Convert<TResult>(Func<T, TResult> converter) {
        return converter(items[0]);
    }
    public void Raise() { var h = MyEvent; if (h != null) h(items[0]); }
    ~MyClass() {
        // 仅演示终结器体可使用外围T，不代表此类型实际需要终结器
        GC.KeepAlive(typeof(T));
    }
}
```

构造器名字是MyClass，不在名字后再声明T；终结器也不写`~MyClass<T2>()`。终结器只演示位置，无非托管资源可释放，实际程序通常不应为这点加入终结器。

<a id="c12-member-negative"></a>
### 属性、索引器、事件的自有参数反例与方法替代

原几种设想分别保留为**非法语法示意**，括号形式看似相似不改变成员种类。

```text
public TValue Data<TValue> { get; set; }              // 泛型属性，非法
public TResult this<TResult>[int index] { get; set; }// 泛型索引器，非法
public event Action<T2> MyEvent<T2>;                 // 泛型事件，非法
public MyClass<T2>() { }                            // 构造器自有T2，非法
~MyClass<T2>() { }                                  // 终结器自有T2，非法
```

原Cache例`public TValue Get<TValue>(string key)`已是普通泛型方法，不是泛型属性。这里保留正确的声明位置作为**类型片段**；它返回默认值，仅为签名演示，不声称从缓存真正取值。

思考区的`public TValue Property<TValue>()`同样已经是普通泛型方法，名字叫Property不改变有圆括号的方法声明；补齐返回体后合法，不能当作“泛型属性编译反例”。

```csharp
public class Cache {
    public TValue Get<TValue>(string key) { return default(TValue); }
    public TValue GetValue<TValue>(int index) { return default(TValue); }
}
```

可以调用`cache.Get<int>("key")`或`cache.GetValue<int>(10)`；原设想`cache.Data<int>`、`cache[10]<int>`、`obj<int>[i]`不是当前C#的对应属性/索引器调用语法。需要不同结果类型时，可选择泛型方法或外围泛型类型，而不是当作现存语法直接使用。

<a id="c12-factory"></a>
### Factory<T>.Create是方法，不是泛型构造器

原正式答用Factory<T>.Create返回default(T)解释构造器，这是普通方法示例。以下完整程序保留它，同时给出原被不当地批评的“非泛型工厂中泛型Create方法”合法替代；两者都返回默认值，未必创建新对象。

```csharp
using System;
public class Factory<T> { public T Create() { return default(T); } }
public class Factory { public T Create<T>() { return default(T); } }
class Program {
    static void Main() {
        Factory<int> factory = new Factory<int>();
        Console.WriteLine(factory.Create());
        Console.WriteLine(new Factory().Create<int>());
    }
}
```

输出0、0。`new Factory().Create<int>()`不是语法错误或无意义形式；设计采用哪一层参数化，取决于希望工厂实例绑定类型，还是每次方法调用选择类型。真正构造器使用外围T的例子是上一节`public MyClass(T value)`。

<a id="c12-generic-operator"></a>
### 操作符没有自己的<TResult>调用语法

原假设希望`a+b`的结果类型独立于MyNumber<T>。下面保留原完整意图为**反例示意**，不是可编译算术程序；除了非法operator类型参数，原例的Value未定义、无约束T的加法也不自动可用。

```text
public struct MyNumber<T> {
    public static TResult operator +<TResult>(MyNumber<T> a, MyNumber<T> b) {
        return (TResult)(object)(a.Value + b.Value);
    }
}
```

写`c=a+b`时，编译器按操作数和现有重载规则选择操作符；当前C#没有`(a+b)<string>`或`a<string>+b`这样的操作符类型实参语法。这个例中的TResult也没有在参数类型出现，普通方法的类型推断不会仅凭预期返回类型补它。语言若要支持还需新增规则，这是当前语言设计选择，不能声称任何编译器原理都“根本不可能实现”。

<a id="c12-generic-math"></a>
### 现代补充：外围T的加法与独立Convert<TResult>

以下完整程序为C# 11/.NET 7+补充，保留原10+20及转double场景，补System.Numerics，并纠正思考区_value/value拼名不一致。

```csharp
using System;
using System.Numerics;
public struct MyNumber<T> where T : INumber<T> {
    private T _value;
    public MyNumber(T value) { _value = value; }
    public static MyNumber<T> operator +(MyNumber<T> a, MyNumber<T> b) {
        return new MyNumber<T>(a._value + b._value);
    }
    public TResult Convert<TResult>() where TResult : INumber<TResult> {
        return TResult.CreateChecked(_value);
    }
}
class Program {
    static void Main() {
        MyNumber<int> a = new MyNumber<int>(10), b = new MyNumber<int>(20);
        MyNumber<int> c = a + b;
        double d = c.Convert<double>(); Console.WriteLine(d);
    }
}
```

输出30。+操作符使用外围T；Convert是普通方法，自有TResult。CreateChecked按数字转换契约检查范围，不保证每种输入都能转换成功。泛型数学正式基础接口在.NET 7引入，配合C# 11静态抽象/虚接口成员；原概览“.NET 6+的INumber”须改正，不作为第四版已具备的能力。[泛型数学官方说明](https://learn.microsoft.com/en-us/dotnet/standard/generics/math)

<a id="c12-members-tables"></a>
### 两张不同用途的成员表

原T的七行表比较自有与外围参数，保留全行。

| 成员 | 可有自有类型参数 | 可使用外围T | 对应示例 |
| --- | --- | --- | --- |
| 属性 | 否 | 是 | MyProp的类型T |
| 索引器 | 否 | 是 | this[int]返回T，须实际访问器实现 |
| 事件 | 否 | 是 | Action<T> MyEvent |
| 操作符 | 否 | 是 | MyNumber<T>的+，仍需合法可用操作 |
| 构造器 | 否 | 是 | MyClass(T value) |
| 终结器 | 否 | 是 | ~MyClass()体中使用typeof(T) |
| 普通方法 | 是 | 是 | Convert<TResult>接受/操作外围T |

原正式答另一个三行表解释设计理由，与上表不同。

| 原分类 | 正确保留的说明 |
| --- | --- |
| 属性/索引器/事件 | 现有语法不给独立参数列表；一些需求可用泛型方法或外围泛型，不说所有需求毫无差别 |
| 构造器/终结器 | C#声明不自有T，外围类型已可参数化；不作“完全没实用场景”的无条件判断 |
| 操作符 | 当前表达式没有相应独立类型实参语法，要支持需额外语言/推断规则 |

原书讨论收益与语言语法成本的取舍，不把聊天中的“99%已覆盖、1%不划算、90%困惑”当设计团队统计或源码事实。

<a id="c12-cli-members"></a>
### CLR方法泛型不能扩写为所有特殊成员都可自有T

原答把这一节说成“全部只是C#不支持，IL层面这些成员都支持”。需区分层次：CLI的GenericParam所有者是TypeDef或MethodDef，Property/Event表本身不是泛型参数所有者。访问器是方法，能表达某些泛型MethodDef形式不代表属性/事件成员自己声明了类型参数；普通泛型方法恰好名叫Finalize也不等于运行时终结器。

CLI标准II.10.5.1明确实例构造器不能取泛型类型参数；终结器的运行时语义来自覆盖System.Object.Finalize的特定签名，不能拿任意同名泛型方法代替。[GenericParam所有者API](https://learn.microsoft.com/en-us/dotnet/api/system.reflection.metadata.genericparameter.parent?view=net-10.0)、[ECMA-335第6版](https://ecma-international.org/wp-content/uploads/ECMA-335_6th_edition_june_2012.pdf)

验证工作区另做了有限探索：两运行时均可加载关联固定object属性的泛型get_Data<T>方法，反射属性类型仍为Object、getter为泛型方法。对一个用MethodBuilder附加T的.ctor试验，CreateType接受了元数据形状，ConstructorInfo却报告IsGenericMethod=False；未验证调用。这个接受观察原样记录，不伪写为TypeLoadException，也不据此宣布合法可用的泛型构造器，更不推翻CLI规范。[方法/构造器反射区别](https://learn.microsoft.com/en-us/dotnet/api/system.reflection.methodbase.isgenericmethod?view=net-10.0)

<a id="c12-constraints"></a>
## 约束分类：具体基类也是主要约束，裸类型是另一个类型参数

原追问从次要约束开始，几轮回答把Farm<T>:Animal错叫裸类型，又说主要约束只有class/struct，最后混称官方/书中分类。按原书及C#语法，应区分：主要约束可包含具体基类或class/struct等规定；次要约束包括接口及另一个类型参数U；构造器new()另列。现代还增加其它形式，不能把新版分类混写成第四版原文。

广义“类型参数约束”可以泛指整个where规则；本书“裸类型约束/naked type constraint”则特指`where T : U`，右侧U也是类型参数。Stream、Animal是具体类，不因此变成裸类型。原书12.8.1把Stream放在主要约束中，与此区分没有矛盾。

<a id="c12-interface-constraints"></a>
### IReadable、IWritable双接口与招聘技能类比

以下完整程序保留原Worker<T>.Test调用Read/Write，同时把原internal接口与public Worker造成的可访问性不一致修齐。

```csharp
using System;
public interface IReadable { void Read(); }
public interface IWritable { void Write(); }
public class Worker<T> where T : IReadable, IWritable {
    public void Test(T item) { item.Read(); item.Write(); }
}
public class Device : IReadable, IWritable {
    public void Read() { Console.WriteLine("Read"); }
    public void Write() { Console.WriteLine("Write"); }
}
class Program { static void Main() { new Worker<Device>().Test(new Device()); } }
```

输出Read、Write。约束让编译器可调用这些成员，类型实参须满足两接口，可为实现它们的类或结构体。招聘英语/法语的类比保留为“必须具备两项能力”；它不是规定只能引用类型，单写class/struct也不能替代具体Read/Write能力。

<a id="c12-base-constraints"></a>
### Farm、Zoo与Animal/Dog家族例

完整程序保留Farm<Dog>.Feed与Zoo<Dog>，补上原Animal没有的Eat方法；具体Animal基类约束本身足以确定相应引用类型关系。

```csharp
using System;
public class Animal { public void Eat() { Console.WriteLine("Eat"); } }
public class Dog : Animal { }
public class Farm<T> where T : Animal {
    public void Feed(T animal) { animal.Eat(); }
}
public class Zoo<T> where T : Animal {
    public void Feed(T animal) { /* 原Zoo例仅展示类型兼容性 */ }
}
class Program {
    static void Main() {
        Farm<Dog> farm = new Farm<Dog>(); farm.Feed(new Dog());
        Zoo<Dog> zoo = new Zoo<Dog>(); zoo.Feed(new Dog());
        // Farm<int> badFarm = new Farm<int>(); // 反例：不满足Animal约束
        // Zoo<int> badZoo = new Zoo<int>();    // 同条件反例
    }
}
```

输出Eat。这个“家族/祖先”类比说明具体基类约束，不是裸类型定义；类型不能因为名字像程序员/Java程序员就满足关系，要存在相应继承。值类型不能派生普通Animal或BaseEntity，原“少见但CLR允许这种值类型子类”是错误归因。

<a id="c12-naked-constraint"></a>
### Converter<TOutput>使用另一个参数作约束

完整程序保留原Hello、Converter<object>与TInput:TOutput，并加int→object说明并不只限类继承。

```csharp
using System;
public class Converter<TOutput> {
    public TOutput Convert<TInput>(TInput input) where TInput : TOutput { return input; }
}
class Program {
    static void Main() {
        var converter = new Converter<object>();
        object result = converter.Convert<string>("Hello"); Console.WriteLine(result);
        object number = converter.Convert<int>(7); Console.WriteLine(number);
        // string bad = converter.Convert<string>("Hello"); // 返回静态类型object，反例CS0266
    }
}
```

输出Hello、7。TInput要满足到TOutput的相应身份/引用/装箱等约束兼容关系；右侧可能由另一参数替换为接口、object等，不等于只允许“父类与子类”。int到object会装箱；裸类型约束独立使用不会自动保证TInput是引用类型。

<a id="c12-repository"></a>
### Repository的class,BaseEntity组合原本不合法

原欲同时表明引用类型并访问Id：

```text
class Repository<T> where T : class, BaseEntity { ... } // 反例：CS0450
```

class和具体基类是此处互斥的主要约束选项，不是“最高与次之优先级叠加”。修为具体基类约束即可，完整程序保留Id、null检查与Save。

```csharp
using System;
public class BaseEntity { public int Id { get; set; } }
public class Item : BaseEntity { }
public class Repository<T> where T : BaseEntity {
    public void Save(T entity) {
        if (entity == null) throw new ArgumentNullException("entity");
        Console.WriteLine(entity.Id);
    }
}
class Program { static void Main() { new Repository<Item>().Save(new Item { Id = 7 }); } }
```

输出7。这里null检查由具体类约束已可表达，不需再写class。若右边是另一个类型参数U，`where T : class,U`可以表达不同组合；不能把具体BaseEntity与U的分类混用。

<a id="c12-class-struct-new"></a>
### class、struct、new()各授予什么能力

历史C# 5完整程序保留两个GetDefault场景及单独的构造器约束：

```csharp
using System;
class Person { public Person() { Name = "created"; } public string Name { get; private set; } }
class Program {
    static T GetDefaultClass<T>() where T : class { return null; }
    static T GetDefaultValue<T>() where T : struct { return new T(); }
    static T Create<T>() where T : new() { return new T(); }
    static void Main() {
        Console.WriteLine(GetDefaultClass<string>() == null);
        Console.WriteLine(GetDefaultValue<int>());
        Console.WriteLine(Create<Person>().Name);
    }
}
```

输出True、0、created。class要求引用类型，允许相应类、接口、委托、数组等类型实参，不只名字写成class的具体类型。struct要求非可空值类型，int、DateTime、枚举和合适struct可满足，Nullable<int>不满足；它已隐含相关构造能力，不再与new()叠写。

new()要求相应可创建类型及public无参构造器，不能只是“任何可访问构造器”，也不能允许abstract类型实例化。构造器约束在历史列表末尾，是语法顺序，不是更低的业务重要性。主要/次要描述的是语法类别，不告诉编译器某引用对象的全部内存布局，也不规定引用类型只分配栈或堆哪一边。

现代struct可声明显式public无参构造器，new T()与default(T)就可能不同；详见[第8章结构体构造说明](第08章-方法.md)。可空引用分析下，class/class?以及T?注解有不同的静态含义；希望返回null时应表达合适的返回可空性，不把“推荐一律class?”当普遍修正。

<a id="c12-stream"></a>
### 用户指出的Stream确实是主要约束例

以下类型与方法体片段保留Stream/FileStream/MemoryStream关系，不访问真实文件。

```csharp
using System;
using System.IO;
public class StreamAlgorithms<T> where T : Stream {
    public void Close(T stream) { stream.Close(); }
}
// 调用方方法体内：
var algorithm = new StreamAlgorithms<MemoryStream>();
var memory = new MemoryStream(); algorithm.Close(memory);
Console.WriteLine(typeof(StreamAlgorithms<FileStream>).IsGenericType);
```

输出True。FileStream只是验证可作实参，没有打开文件；MemoryStream是临时内存对象。约束保证Close成员可在T上调用，不代表所有Stream具体方法都不会异常。where T:IComparable可由int/string满足接口约束；where T:U是另一个参数关系，三者应按原最后一张表分别理解。

<a id="c12-method-constraint-shadow"></a>
### 外围T1/T2与方法自己的T1/T2不能混为一组

原MyClass<T1,T2>.Method<T1,T2>例又声明同名方法参数，这些是另外一组参数，会遮蔽外围并产生CS0693警告。下面完整程序将方法参数改名，但保留同一裸类型约束场景，并演示类继承之外的int/object兼容。

```csharp
using System;
public class MyClass<T1, T2> {
    public void Method<U1, U2>(U1 t1, U2 t2) where U1 : U2 {
        U2 converted = t1; Console.WriteLine(converted);
    }
}
class Program {
    static void Main() {
        var value = new MyClass<string, string>();
        value.Method<string, object>("Hello", new object());
        value.Method<int, object>(7, new object());
    }
}
```

输出Hello、7。外围string/string并未约束这两次方法实参；要约束外围参数，应将where放在类型声明对应位置，而不是重新声明另一组同名参数。

<a id="c12-constraint-tables"></a>
### 原两张约束表：分类与具体语法

原四行表的“优先级”改为实际分类/书写顺序，保留四种角度。

| 类别 | 原示例语法的正确归属 | 作用 | 书写条件 |
| --- | --- | --- | --- |
| 主要约束 | class、struct或具体基类（现代有其它形式） | 给出相应类型能力/类别 | 同一参数不能写class再写BaseEntity |
| 裸类型参数约束 | where T:U；BaseClass不是这个类别 | 由另一个参数规定兼容关系 | 属次要，可结合适当主要约束 |
| 接口约束 | where T:IDisposable等 | 要求接口能力 | 可列多个，按语法约束组合 |
| 构造器约束 | where T:new() | public无参且可创建的相应类型 | 历史列表末尾，struct/unmanaged不与它重复叠写 |

原最后三行表保留Stream、IComparable与U的具体比较。

| 语法 | 名称 | 含义 | 原例及边界 |
| --- | --- | --- | --- |
| where T:Stream | 具体类约束，本书主要约束例 | Stream或相应派生类型 | FileStream、MemoryStream满足；不是裸类型 |
| where T:IComparable | 接口约束 | 满足对应接口契约 | int、string满足，可为值/引用 |
| where T:U | 类型参数/裸类型约束 | T满足到另一个参数U的相应约束兼容 | 不限类继承，身份、接口及装箱等要按规则判断 |

原“户口本与职位”“种族与祖宗”“生死与辈分”类比可以辅助区分类别与相应关系，但class/struct不是确定全部布局的户口本，Stream仍是主要约束，U也不必是普通类祖先。技能如游泳/骑车可类比多个接口；程序员后代/哺乳家族适于具体基类关系，不能代替裸类型兼容规则。

<a id="c12-verifiability"></a>
### 约束、default、null与操作符的边界

原概览提到“与null比较、==、+、++”的问题，须拆开，而非一律说T都不能比较。完整程序：

```csharp
using System;
class Program {
    static bool IsNull<T>(T value) { return value == null; }
    static T DefaultValue<T>() { return default(T); }
    static void Main() {
        Console.WriteLine(IsNull(1)); Console.WriteLine(IsNull<string>(null));
        Console.WriteLine(DefaultValue<int>());
    }
}
```

输出False、True、0。无约束T与null比较有允许的规则，default(T)也无需new()；两个无约束T值的`a==b`、`a+b`、`++a`不会自动按未来数值类型重绑定，原书背景下须相应合法能力或另行设计，不能仅凭运行实参是int就通过泛型定义检查。现代INumber等是明确增加的操作协议，不是把无约束T也放宽成动态。

显式转换也须说明可能失败的条件；类型参数约束给出编译器可证明的转换和成员能力，不等于任意T都能转任意结果类型。重写虚泛型方法时约束主要由基方法继承，历史重复声明会报CS0460；现代为可空性/适当场景允许class、struct或default等声明例外，不能继续说永远一字不能重声明。[where官方规则](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/where-generic-type-constraint)

现代另有unmanaged、notnull、Enum/Delegate约束支持及ref struct相关反约束，依各语言版本与运行时支持；不混入C# 5原条款。C# 7.3增加的枚举/委托等约束允许`where T:struct,Enum`这样的枚举能力组合，仍没有`where T:int`作为普通具体值类型基类约束的语法能力。[类型参数约束规范](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/classes#1525-type-parameter-constraints)

<a id="c12-overloads"></a>
### 泛型方法推断与非泛型重载的选择

原概览说编译器优先具体版本再泛型版本，不能当全局规则。先推断适用泛型候选，再按更佳成员等规则决定；相应条件平局时非泛型候选可以胜出。完整程序保留这个导读并用两种情形区分：

```csharp
using System;
class Program {
    static string M(int value) { return "concrete"; }
    static string M<T>(T value) { return "generic"; }
    static string N(object value) { return "object"; }
    static string N<T>(T value) { return "generic"; }
    static void Main() {
        Console.WriteLine(M(3));
        Console.WriteLine(M<string>("x"));
        Console.WriteLine(N(3));
    }
}
```

输出concrete、generic、generic。M(3)在这一对候选条件下选非泛型int版本；N(3)泛型T=int的身份转换优于到object的转换，不能强行优先非泛型。方法类型参数可从实参推断，返回值预期一般不代替缺失实参的推断依据；编译器按约束检查已推断/指定类型，不是运行时根据数据临时选择T。[重载选择规范](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/expressions#12643-better-function-member)
