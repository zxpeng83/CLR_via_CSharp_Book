    文档中的明确警告：文档8.1节特别强调了一个与此相关的危险做法：不要在构造器中调用虚方法。这正好对应了你担心的“提前访问”问题的一种延伸情况。如果基类构造器调用了一个虚方法，而该虚方法在派生类中被重写，那么派生类的重写方法会在派生类自身的构造器执行之前就被调用。此时，如果重写方法访问了派生类中定义的字段，它访问到的就是默认值0/null，而不是派生类构造器将要赋予的值。文档称这会导致“无法预测的行为”。

总结

  1. 1.1.
    调用时机不可控：C#语言通过语法规则强制规定，对基类构造器的调用必须发生在派生类构造器函数体执行之前。你无法在子类的构造器函数体内部决定何时调用它。
  2. 2.2.
    访问安全有保障，但逻辑需谨慎：由于CLR的内存归零机制，技术上不会因为访问未调构造器的基类成员而引发内存访问违例的运行时错误。但是，任何不遵循“基类构造器优先”执行顺序的代码（C#已从语法上杜绝了这种情况，但某些特殊操作如反序列化或通过FormatterServices.GetUninitializedObject创建对象除外），如果访问了基类成员，都只能得到默认值，从而引发逻辑错误。文档特别指出的“构造器中调用虚方法”就是典型陷阱。
因此，你无需担心“提前访问导致报错”，因为C#的语法设计已经防止了这种情况的发生。你更应该关注的是遵循构造器链的正确初始化顺序，以避免逻辑上的错误。

我们之前讨论的顺序是“自上而下”的递归过程。对于单个类（无论是基类还是派生类），其构造过程在自身内部的步骤顺序是固定的：内联初始化 -> 调用基类构造器 -> 执行构造器函数体。
但请注意，这个“调用基类构造器”步骤会触发对基类整个构造过程的递归。所以，从整个对象构造的顶层来看，顺序是沿着继承链从最顶端的基类（如System.Object）开始，逐步向下完成每个类的初始化，然后返回，继续执行下一层类的构造器函数体。
你提到的“2=》3=》2=》...”看起来像是一个循环，但实际上这是一个递归调用链，而不是循环。让我用更清晰的步骤来描述：
假设有继承链：Object -> A -> B
当我们 new B() 时，构造顺序如下：
  1. 1.1.
    为B的实例分配内存，并将所有字段归零（包括A和Object中定义的字段）。
  2. 2.2.
    开始构造B：

    步骤2（调用基类构造器）：调用A的构造器。
    2.1 进入A的构造过程：
    步骤1（A的内联字段初始化）：执行A中声明的字段的内联初始化代码。
    步骤2（调用基类构造器）：调用Object的构造器。
    2.1.1 进入Object的构造过程：
    步骤1（Object的内联字段初始化）：Object没有内联初始化（假设没有），或者有则执行。
    步骤2（调用基类构造器）：Object没有基类，所以这一步什么都不做，直接进入下一步。
    步骤3（执行Object构造器函数体）：执行Object的构造器代码（如果有）。
    2.1.2 返回A的构造过程，继续执行步骤3。
    步骤3（执行A构造器函数体）：执行A的构造器函数体中的代码。
    2.2 返回B的构造过程，继续执行步骤3。
    步骤3（执行B构造器函数体）：执行B的构造器函数体中的代码。
所以，整个顺序是：B的内联初始化 -> A的内联初始化 -> Object的内联初始化 -> Object的构造器函数体 -> A的构造器函数体 -> B的构造器函数体。
注意，内联初始化是在进入每一层的构造器函数体之前，在该层构造过程的第一步就执行的。所以，内联初始化的顺序是沿着继承链从最派生类到基类，然后构造器函数体的执行顺序是从基类到派生类。
但是，请注意，我们之前说“对于每一个类，顺序是：内联初始化 -> 调用基类构造器 -> 执行构造器函数体”。在调用基类构造器时，会递归进入基类的构造过程，而基类的构造过程同样遵循这个顺序。所以，从整体上看，内联初始化是“自上而下”（从最派生类到基类）执行，而构造器函数体是“自下而上”（从基类到最派生类）执行。
你提到的“2=》3=》2=》...”可能是在理解递归调用时产生的困惑。实际上，每一步都是线性的，没有循环。在B的构造过程中，执行到步骤2（调用基类构造器）时，会跳转到A的构造过程，然后A的步骤2又会跳转到Object的构造过程，然后Object完成步骤3后返回到A的步骤3，然后A完成步骤3后返回到B的步骤3。所以，整个顺序是：B的步骤1 -> A的步骤1 -> Object的步骤1 -> Object的步骤3 -> A的步骤3 -> B的步骤3。

  1. 1.1.

  2. 2.2.
    基于栈的值类型字段（即局部值类型变量）：

  3. 3.3.
    文档中的“注意”说我们可以忽略这个区别，认为所有值类型字段都会被初始化为0或null：
    这是因为，对于引用类型中的值类型字段，CLR自动初始化为0；对于栈上的值类型局部变量，C#编译器强制我们必须先赋值再使用，所以我们也不会读到随机值。因此，在实际编码时，我们可以认为值类型的字段总是有默认值0（或null）。
