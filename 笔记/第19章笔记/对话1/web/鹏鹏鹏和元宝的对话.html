先给结论

Nullable<Int32> 确实是 struct（值类型），但 C# 编译器对 Nullable<T> 开了专属语法糖：null 字面量赋值给 Nullable<T> 变量时，编译器会自动把它转成 new Nullable<Int32>()，也就是 HasValue = false 的那个"空值"。

拆开看

Nullable<T> 的内部大致是这样（简化）：
csharp
public struct Nullable<T> where T : struct
{
    private readonly T _value;
    private readonly bool _hasValue;

    public bool HasValue => _hasValue;
    public T Value => _hasValue ? _value : throw new InvalidOperationException();
}
它的"空"并不是引用类型的那种 null 引用，而是 _hasValue = false + _value = default(T)​ 这种状态。

那 Nullable<Int32> y = null; 发生了什么？

源码：
csharp
Nullable<Int32> y = null;
编译器并不真的把一个 null 引用塞进值类型变量（那也不可能，栈上/结构体内存里放不了引用类型的 null 语义），而是翻译成等价于：
csharp
Nullable<Int32> y = new Nullable<Int32>();   // HasValue = false
或者用 default：
csharp
Nullable<Int32> y = default;                 // 一样的效果
C# 规范里给 Nullable<T> 专门定了一条隐式转换：从 null 字面量（更准确说是 the null literal）到 Nullable<T> 存在隐式转换，结果就是 default(Nullable<T>)。

为什么只有它能这么玩

这是 C# 编译器 + CLR 只认 Nullable<T> 这一个类型的特权：
  • ••
    普通 struct S { } 写 S s = null; ❌ 编不过，因为值类型没有到 null 的隐式转换
  • ••
    唯独 Nullable<T> 被语言规范点了名，编译器看到 T? / Nullable<T> 就走这套特殊规则（包括 == null、!= null、操作符提升这些，后面章节会挨个讲）

再验证一下装箱时的"撒谎"（连到第 19 章后半段） 

csharp
Nullable<Int32> y = null;
object o = y;      // 装箱：y.HasValue == false → 直接给 o 赋 null，不是装箱成 object
Console.WriteLine(o == null); // True
这就是 Richter 说的"Nullable 装箱特殊规则"——空的 Nullable 装箱 = 真正的 null 引用，而不是一个装了 Nullable<T> 的箱子。反过来拆箱时，null 也能拆回"空的 Nullable"，双向对称。
所以你这个疑问的本质是：null 在这里不是"引用为空"，而是"Nullable 的空状态"的语法糖，编译器帮你 new 了一个 HasValue = false 的值，只是写起来像引用类型那样自然。
